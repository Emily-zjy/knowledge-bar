# Knowledge Bar PRD 写作规范

本规范来自 `prd-references/images` 中的产品经理自查表和 PRD 写作方法资料。后续 Knowledge Bar 的 PRD、迭代文档、需求变更说明，都应优先遵循本文件。

## 1. 写作原则

1. PRD 不是功能罗列，而是说明为什么做、为谁做、做成什么样、边界在哪里。
2. 需求必须能被设计、前端、后端、测试理解并执行。
3. 对每个功能说明前置条件、触发条件、正常流程、异常流程、数据变化、反馈方式。
4. 不用连续大段文字堆叙述，重要信息用表格、流程、清单承载。
5. P0 只写第一版必须完成的闭环，P1/P2 只作为后续规划，不混进 MVP。
6. 文档中必须标注不做什么，避免范围膨胀。

## 2. PRD 推荐结构

1. 修订记录
2. 背景简介
3. 目标与价值
4. 用户与使用场景
5. 范围说明
6. 功能清单
7. 用户流程
8. 页面与交互说明
9. 数据与权限规则
10. 异常与 Corner Case
11. 非功能需求
12. 验收标准
13. 后续迭代规划

## 3. 功能说明标准

每个功能尽量覆盖：

| 项目 | 说明 |
| --- | --- |
| 功能名称 | 功能的唯一名称 |
| 优先级 | P0/P1/P2 |
| 使用角色 | 登录用户/游客/系统 |
| 前置条件 | 使用该功能前必须满足什么 |
| 触发条件 | 用户点击、输入、上传、保存等动作 |
| 主流程 | 成功路径 |
| 异常流程 | 失败、空数据、权限不足、网络错误等 |
| 页面反馈 | Toast、Loading、按钮禁用、错误提示等 |
| 数据变化 | 创建、更新、删除哪些数据 |
| 验收标准 | 什么情况算完成 |

## 4. 交互自查清单

1. 页面是否有空状态、加载状态、失败状态。
2. 按钮点击后是否有反馈，是否避免重复提交。
3. 表单是否有必填、格式、长度校验。
4. 删除类操作是否有确认。
5. 游客和登录用户看到的功能边界是否清楚。
6. 用户输入的数据是否会保存，保存失败是否提示。
7. 上传图片是否限制类型、大小、失败原因。
8. AI 生成是否有 Loading、失败重试、空内容拦截。
9. 导出文件是否有命名规则和失败提示。
10. 页面刷新、返回、跳转后是否保留用户预期数据。

## 5. 数据与权限自查清单

1. 登录用户的数据必须归属到用户。
2. 游客数据默认只本地临时保存，不能假装云端保存。
3. 用户不能访问、编辑、删除他人的知识库。
4. 删除知识库需要同时处理文档内容、标签、图片、思维导图等关联数据。
5. AI 生成结果只保存最新版，历史版本第一版不做。
6. P0 不做会员、次数限制、团队空间，但要预留后续扩展空间。

## 6. 本项目特殊约束

1. 产品定位：AI 个人知识库 + 可编辑思维导图生成器。
2. 第一版不称为复杂知识图谱产品，避免实现范围过大。
3. 第一版重点闭环：注册/登录 -> 创建知识库 -> 自由编辑内容 -> AI 生成思维导图 -> 保存/导出。
4. UI 方向：简约、高级、知识酒吧主题、暖橙棕夜场品牌感。
5. 第一版不做 OCR、网页链接解析、Notion 式块编辑器、AI 聊天助手、学习计划、会员限制。
